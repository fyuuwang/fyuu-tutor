怎么组织一个 skill 的文件夹

不是写 SKILL.md 的内容，是决定「哪些文件放哪、什么时候该拆出来」。市面官方方案 + 你本机真实样板，一个原则讲透。

你撞过的墙

你把几十种公文（采购、请示、评分表……）全塞进一个 skill。结果换一种文体，格式就乱。你问过自己「总不能写几十个 skill 吧」——对，不能。但问题不是 skill 太少，是结构不对。这一节讲的就是这个结构。

一个原则管全部：Progressive Disclosure（渐进式披露）

所有官方方案——Anthropic 文档、GitHub 仓库、社区教程——背后都是这同一个原则：

SKILL.md 是门厅，其他文件是按需才进的房间。门厅永远开着（每次用 skill 都会读），所以要精简；详细的资料、脚本、模板放进各个房间，需要时才开门进去拿。这样门厅不会塞爆，但你又随时能拿到细节。

对应到你 50 种公文的问题：不要把 50 种文体的写法全堆在 SKILL.md（门厅塞爆了，每次都串味）。门厅里只放「判断这是哪种文体 + 去哪个房间拿模板」的路由逻辑；每种文体一个房间（一个文件），用到才开。这就是路由模式（图谱④），它的物理实现就是文件夹结构。

标准四件套（官方共识）

一个 skill = 一个文件夹。文件夹里最多这四样：

SKILL.md（必需）

门厅。开头是 YAML 元数据（至少 name + description），后面是指令。永远被读，所以要精简（官方建议几百行以内）。只放：做什么、什么时候用、该去哪个房间找细节。

scripts/（可选）

放确定性的脚本——Python、Shell。凡是 model 不擅长的（精确计算、格式转换、文件处理），交给脚本。本机 pptx / docx skill 的 scripts/ 里就是打包解包、清洗 OOXML 的 Python。

references/（可选）

放参考文档——长说明书、API 用法、规则手册。SKILL.md 里写「详细规则见 references/xxx.md」，用到才读，不污染门厅。

assets/（可选）

放模板、样例、数据文件。你的公文 skill 里，国标格式模板、各文体的范文就该放这。

标准结构示意：

my-skill/文件夹名 = skill 名
SKILL.md必需：元数据 + 指令（门厅）
scripts/可选：脚本（.py / .sh）
references/可选：参考文档（按需读）
assets/可选：模板 / 数据 / 样例

三个复杂度档（你本机都有样板）

档① 最小：只有 SKILL.md

本机样板：grill-me、teach、write-a-skill。逻辑短、没脚本、没模板——一个文件搞定。别为了「显得专业」硬拆。

档② 典型：SKILL.md + 几个参考文件

本机样板：pptx（SKILL.md + pptxgenjs.md + editing.md）。主线精简放 SKILL.md，大段专题资料拆成几个 .md 平级摆放。这是大多数 skill 该有的样子。

档③ 复杂：SKILL.md + scripts/ + 数据 / schema

本机样板：docx（带 scripts/office/schemas/ 一堆 .xsd）。要处理二进制格式、跑确定性逻辑——才上 scripts/ 和数据目录。你 MDG skill 改 XML 那套，就够格上这档。

决策规则：什么时候该拆出新文件

问题怎么办
SKILL.md 超过约 300-500 行了？拆。把大段专题内容挪进 references/xxx.md，SKILL.md 留一句「详见……」。
有一段确定性逻辑（计算、格式处理、文件操作）？写成脚本放 scripts/，别让 model 用 prompt 硬干（会飘）。你 MDG 改 XML、公文引号统一，都该是脚本。
同一个 skill 要服务多种「变体」（文体 / 场景）？SKILL.md 只放路由（判断是哪种 + 指向哪个文件），每种变体单独一个文件放 assets/ 或 references/。这就是治你 50 种公文的方法。
有模板 / 范文 / 数据表要复用？放 assets/。国标公文格式模板、各文体范文都归这。

落到你自己的 skill

公文写作 skill（档③，重构）

gongwen/SKILL.md门厅：判断文体 + 路由 + 通用规则
references/caigou.md采购文件写法
references/qingshi.md请示写法（含子类）
references/pingfen.md评分表写法
assets/guobiao-template.docx国标格式模板（版面在这，不在 prompt）
scripts/normalize.py统一引号 / 全半角（确定性后处理）

版面交给模板文件，不交给 model——这同时治了「页边距乱 / 页脚漏」那批毛病（图谱①排版边界）。

MDG skill（档③）

mdg/SKILL.md门厅：流程 + 字段规则入口
references/field-rules.md客商各字段校验规则（按需查）
scripts/extract.py调 OCR 抽数据（感知边界交给工具）
scripts/build_xml.py直接生成 MDG 识别的 XML（钉死 substrate）
